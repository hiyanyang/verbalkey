# Verbalkey

**Windows 上的本地语音输入。按住热键说话，浮窗里看着字出来，松开就写进光标。**

识别、断句、去口水词、整理成书面语，全部在这台机器上算完。录音不落盘、不上传，拔了网线照样能用。

- 识别：Qwen3-ASR-0.6B int8（sherpa-onnx，纯 CPU，不需要显卡）
- 分句：Silero VAD + 整段重解（松手后拿整轮音频重算一遍，修分段边界的错字）
- 整理：本地规则（去口水词）+ llama.cpp（书面化，可选）
- 界面：PySide6 浮窗 + 设置页，托盘常驻
- 拼音：可选，附带小狼毫 + 雾凇拼音的一套托管配置

---

## 为什么做这个

**第一，声音不该离开这台机器。**

好用的语音输入大多是云端的：免费的有额度和登录门槛，付费的按分钟计费，共同点是你说的话要发到别人的服务器上。而语音输入最常用的场合，恰恰是内容最不该外泄的场合——病历、陪护记录、家属电话、合同条款、客户报价、还没发布的选题。这些不该变成某家公司的训练语料，也不该赌它的隐私政策。

所以这个项目的目标定得很死：**模型放本地，CPU 能跑，断网可用。** 宁可慢一两秒，也不把音频发出去。

**第二，中文口语转文字，难点不在"识别"，在"收拾"。**

试过现成方案之后撞了两个坑：

1. **长句被切成小段分别识别，段与段之间丢字。** 同一段 11 秒的音频，在 2.9 秒处切开分别识别，拼出来是"拉到**机**上面……这个**它上上面**"；整段重算一遍是"拉到**车**上面……**轮胎上面**"。差的不是模型精度，是边界处的上下文没了。
2. **口语到书面语这一层，要么不做，要么做过头。** 通用大模型会把"我想问一下那个陪护一天多少钱"改成面目全非的句子，也会把"考虑考虑"这种正常叠词压成病句。

于是有了两层处理：**松手后整段重解**（只修边界丢字，不改措辞），以及**分档的整理**（去口水词走确定性规则，书面化才动模型）。细节见[口述整理怎么配](#口述整理怎么配)。

## 隐私：边界写清楚

### 音频

- 只在内存里存在，识别完即释放。**程序不写任何音频文件**，也不会把它发给任何人。
- 没有"上传失败重试"这类逻辑，因为压根没有上传这条路。

### 唯一会联网的地方

| 什么时候 | 连哪里 | 传什么 |
|---|---|---|
| 首次启动，你点「开始下载」之后 | ModelScope（模型）、GitHub（llama.cpp） | 只下载，不上传 |
| 引导窗口里勾了拼音，同一次点「开始下载并安装」 | GitHub（小狼毫、雾凇词库） | 只下载，不上传 |
| 你点「设置 → 拼音输入法 → 词库更新」 | GitHub（iDvel/rime-ice） | 只下载，不上传 |

三处都是**你点了才动**：程序启动不会自己去连任何东西，也不会在后台悄悄补下载。
除此之外没有任何对外连接——不检查更新、不埋点、不发统计、没有账号体系、没有许可证校验。
装完之后断网，识别、整理、拼音全都照常。

### 本地会留下什么（介意可以删）

| 文件 | 内容 | 删掉的后果 |
|---|---|---|
| `data/hotwords/corpus.jsonl` | 成对语料：每说完一句记一条「分段草稿 → 整段重解」的对照。这是学你常被听错的词的原料 | 失去学习数据，识别照常 |
| `logs/app.log` | 运行日志，**含每次上屏的文本**，4 MB × 4 自动轮转，封顶 16 MB | 出问题不好排查 |
| `config.json` | 你的设置 | 回到默认值 |

这三个都是**明文**，都在程序目录里。要把日志发给别人看之前，先自己翻一眼。

## 特点

| | |
|---|---|
| **完全离线** | 识别和整理都用本地模型，CPU 推理。没有额度、没有计费、不看网络脸色 |

| **两级纠错** | 整段重解修边界丢字；「从改正里学」把重复出现的错听记成文本替换，零幻觉风险 |
| **不打断输入** | 默认等终稿一次性写入光标，不会先把半成品塞进去再改；你切走窗口它就不写，只留剪贴板 |
| **两档整理** | 去口水词是毫秒级规则，不启模型；书面化才跑 llama.cpp |
| **可选拼音** | 想连中文打字一起用，可以托管小狼毫 + 雾凇拼音，语音和拼音共用一个「中/英」图标 |

## 需要什么

### 直接用（推荐）：不用装 Python，不用命令行

- Windows 10 / 11（x64），不需要显卡、不需要 CUDA
- 磁盘约 1.2 GB：程序 182 MB + 识别模型 940 MB（要书面化再加 940 MB）
- 内存：识别常驻约 1.1 GB；开书面化再 +2.3 GB

流程就三步：**下载一个 72 MB 的压缩包 → 解压 → 双击 `Verbalkey.exe`**。

第一次启动会弹一个窗口，把「要下什么、多大、还剩多久」列清楚（识别模型 942 MB，
书面化 964 MB，拼音 29 MB），你勾选后点一次「开始下载并安装」。
下完托盘出现粉色图标，按住右 Alt 说话就能上屏。

**全程你只需要点两次**：一次「开始下载」，一次装拼音引擎时系统弹的管理员授权框
（Windows 的规矩，装输入法必须授权，这个绕不过去）。勾了拼音的话，下载、装引擎、
铺词库、编译、改名字全在这一个窗口里自己跑完，不用再去设置页点第二遍。

断网中断也没关系：下次打开会接着下，不会从头来。装完之后**全程离线**，不再联网。

### 自己改代码 / 自己打包：需要 Python

- Python 3.10 以上（开发环境 3.13.14，安装时勾选 "Add python.exe to PATH"）
- 其余同上

| 内容 | 说明 |

| 不带 | 大小 | 为什么 |

| 书面化模型 + llama.cpp | 964 MB | 同上，而且不是所有人都要书面化 |
| 小狼毫引擎 + 雾凇词库 | 29 MB | GPL-3.0 第三方二进制 |
| `config.json` / `data/` / `logs/` | — | 属于别人机器上的隐私，绝不能进发布包 |

## 安装

### 方式一：用发布包（普通用户）

1. 从 [Releases](../../releases) 下 `Verbalkey-x.y.z-win64.zip`
2. 解压到任意目录（建议纯英文路径，别放 `C://Program Files` —— 那里写不进模型）
3. 双击 `Verbalkey.exe`，按窗口提示点「开始下载并安装」

不需要安装 Python，不需要管理员权限（只有装拼音引擎那一步会弹一次授权框）。
整个文件夹可以拷到 U 盘或别的电脑，**挪位置要整个文件夹一起挪**，别只拷 exe。

### 方式二：从源码跑（要改代码）

```bash
python -m venv .venv
.venv\Scripts\python.exe -m pip install sherpa-onnx PySide6 sounddevice numpy opencc-python-reimplemented
.venv\Scripts\python.exe tools\fetch_models.py --group vad,asr
.venv\Scripts\python.exe entry.py
```

也可以直接跑 `install.bat`，它把上面三步串起来了（`install.bat full` 连书面化一起装）。
只有这条路需要 Python。

### 模型下载器

引导窗口和命令行用的是同一份清单（`src/fetch.py`），也可以单跑：

```bash
.venv\Scripts\python.exe tools\fetch_models.py --check          # 只看缺什么
.venv\Scripts\python.exe tools\fetch_models.py --group vad,asr  # 只下识别
.venv\Scripts\python.exe tools\fetch_models.py --group pinyin   # 只下拼音组件
.venv\Scripts\python.exe tools\fetch_models.py --all            # 全下
```

特性：**断点续传**、**已有的跳过**、**多源回退**（ModelScope 不通换 GitHub 镜像）、
**下完核对大小**。文件清单与来源见[模型](#模型)一节。

## 第一次使用

1. **看托盘**：右键托盘图标 → 设置，确认「语音与识别」里麦克风选的是你在用的那个。
2. **按住右 Alt 说一句话**，说完松开。浮窗会先滚出草稿，随后被终稿替换，最后一次性写进光标。
3. **如果输入框没反应**：点一下任意输入框让光标在里面，再说一次。程序不会替你抢焦点。

第一次说完到出字会比后面慢一点（模型冷启动 4–5 秒，只在启动时发生一次）。

## 日常用法

| 操作 | 效果 |
|---|---|
| 按住 右 Alt | 录音，浮窗实时滚草稿 |
| 松开 | 整段重解 → 写进光标（开着整理就等整理完一次写入） |
| 短按 右 Ctrl | 用整理版替换刚上屏的原文（45 秒内有效） |
| 点浮窗「用整理版」 | 同上，懒得按键时用鼠标 |
| 点浮窗右上角 × | 收起浮窗，这轮结果丢掉 |
| 单击托盘 | 打开设置 |
| 右键托盘 | 设置 / 重载模型 / 退出 |

触发方式可以改成「按一下开始、再按一下结束」，适合长段口述。录音键可选右 Alt（默认）、右 Ctrl、右 Shift、CapsLock、F5、F8、反引号。

确认键默认右 Ctrl，和录音键分开，不会打架。

## 设置项说明

**通用** — 开机自启、浮窗位置、浮窗字号（小 16 / 标准 18 / 大 20）、上屏方式（自动 / 仅 Ctrl+V / 仅发消息）。

**热键** — 触发方式 + 录音键 + 整理确认键。改完立即生效。已知限制：全屏程序和以管理员身份运行的窗口会拦掉全局热键。

**语音与识别** — 麦克风设备、推理线程。断句参数不对外开放，原因见[技术笔记](#断句参数为什么不开放)。

**文本** — 繁体转简体（Qwen3-ASR 常输出繁体，建议开）、替换词表（`原文=替换后`，一行一条）、热词（逗号分隔，**建议不超过 3 个**，填多了模型会把词表当正文念出来）。

**口述整理** — 三档强度、整理结果的给法、llama-server 与 GGUF 路径。

**拼音输入法** — 状态、输入方案（全拼/双拼）、候选窗样式、重新编译、词库更新。

**识别模型** — 切换已安装的模型，或打开目录自己放新的进去。

## 口述整理怎么配

三档，按场合选：

- **关闭** — 一个字节都不改。会议记录、病历这类要逐字忠实的场合用它。
- **去口水词** — 删掉「嗯、啊、那个、就是说」和结巴重复，不动措辞。**走本地正则，毫秒级，不启模型、不占内存**，真正的"说完就干净"。
- **书面化** — 补标点、理顺断句，跑本地小模型。带 few-shot 示例，效果比零样本稳。

为什么去口水词不用模型：1.7B 在这一档上摇摆得厉害，同一句话有时一个字不改，有时把「考虑考虑」改成「考虑」（把正常叠词压成病句）。确定性的活儿交给规则。

### 整理结果怎么给你

- **等整理完一次写入**（默认，`paste_mode=polished`）：松手后输入框一个字不写，浮窗滚草稿，终稿出来一次性写入。干净，但松手到出字要等重解 + 整理。
- **先写原文，再按确认键替换**：早一点看到字，代价是文字会跳变。

等着出字的时候如果你切走了窗口，程序**不会**抢回焦点、也不会往旧窗口塞字——结果留在剪贴板，浮窗提示按 Ctrl+V。

### 速度是怎么压下来的

1. **按下热键就开始点火**：llama-server 冷启动 2 秒多，等松键才起就要干等；现在你还在说的时候它已经在加载，进程优先级调低，不跟识别抢 CPU。
2. **system 指令与 user 原文分开**：指令固定，llama-server 的前缀 KV 缓存能命中，同一句话第二次起快一倍多。
3. **关掉 Qwen3 的思考模式**：不关会多烧 160 token、多花 8 秒。
4. **常驻内存开关**：开了省掉每次 2 秒冷启动，代价常驻约 2.3 GB。

## 出问题怎么查

先看日志：`logs/app.log`（源码运行时在项目根，exe 运行时在程序目录）。启动第一行会打印版本和当前配置，很多问题看一眼就明白。

下面按"你可能卡在哪一步"排。

### 第 1 步：首次启动，下载这一步

用发布包的人只会卡在这里，逐个症状对照：

| 现象 | 原因 | 处理 |
|---|---|---|
| 双击没反应，托盘也没图标 | 被杀软拦了，或解压不完整 | 看 `logs/crash.log`；重新解压一次；把整个文件夹加进杀软白名单 |
| 弹窗提示"已经在运行" | 单实例锁，之前那份还没退 | 从托盘退出旧的那份。日志里会写 `检测到已有实例` |
| 下载一直 0% 不动 | 连不上 ModelScope | 点「稍后再说」，等网络好了从托盘「下载模型与组件…」再来；已下的部分不会重来 |
| 下到 90% 断了 | 网络中断 | 重新打开窗口点「重试」，会续传 |
| 提示某些文件"没下完" | 校验没通过（大小不符） | 点「重试」；反复失败就删掉 `models/` 里那个文件重下 |
| 装拼音时弹授权框 | 装引擎要管理员权限 | 点「是」。点了「否」窗口会写「拼音输入法没装成」，点「再试一次」即可，文件不会重下 |
| 拼音那行写着"待安装" | 文件下过了，但引擎没装完 | 这一行默认帮你勾好，点下面的按钮就行 |
| 下载完仍提示找不到模型 | 目录写不进去 | 别放在 `C://Program Files`，挪到用户目录再试 |

**从源码装的人**才会遇到下面这些（发布包没有这一步）：

| 现象 | 原因 | 处理 |
|---|---|---|
| `install.bat` 闪一下就没了 | 没装 Python 或没加 PATH | 脚本现在会自己提示并给出下载地址 |
| 装依赖超时 / 一片红 | pypi 网络问题 | 换清华源，脚本报错时已经把命令打出来了 |
| 模型下到一半失败 | 网络中断 | 再跑一次 `install.bat`，会接着下 |

### 第 2 步：装完了，启动没反应

| 现象 | 原因 | 处理 |
|---|---|---|
| 双击 `start.vbs` 后托盘没图标 | 启动时崩了 | 改用 `run.bat` 看控制台输出，或看 `logs/app.log` 末尾和 `logs/crash.log` |
| 弹出标题为 "Verbalkey" 的对话框 | 已经在跑了（单实例锁） | 看托盘；真要重开就先从托盘退出。日志会写一行 `检测到已有实例，本次启动退出` |
| 启动卡 4–5 秒才出图标 | 正常，在加载识别模型 | 等它 |
| 提示"未找到识别模型" | 模型没下全或目录结构不对 | 跑 `tools/fetch_models.py --check`，再对照[模型](#模型)一节的目录结构 |

### 第 3 步：按住热键没反应

| 现象 | 原因 | 处理 |
|---|---|---|
| 完全没反应，浮窗也不弹 | 当前窗口是全屏游戏 / 以管理员身份运行 | 全局热键会被这类窗口拦掉。先用普通窗口点一下 |
| 浮窗弹了但没字，松手没结果 | 麦克风选错或被别的程序独占 | 设置 → 语音与识别 → 换设备。Windows 的"默认设备"改了之后，这里可能要重新选一次 |
| 换了耳机 / 拔了麦克风之后不灵 | 设备句柄失效 | 设置里重新选一次设备（不用重启程序） |
| 键位奇怪，按 Alt 触发了别的菜单 | 录音键和别的软件冲突 | 设置 → 热键，换成 F5 / F8 / 反引号 |

### 第 4 步：有字，但没进输入框

| 现象 | 原因 | 处理 |
|---|---|---|
| 浮窗有结果，输入框空的 | 光标不在可输入的地方 | 点进输入框再说。文本已经在剪贴板，按 Ctrl+V 也能拿到 |
| 浮窗提示"已复制，按 Ctrl+V" | 等终稿期间你切了窗口 | 故意的：不抢焦点、不往旧窗口写。回目标窗口粘一下 |
| 粘进去的是上一条 | 顺序没问题，是延迟 | 结果会排队按顺序补写，等下一段说完 |
| 目标程序不接受模拟粘贴 | 少数以管理员权限运行的程序 | 用浮窗的"复制"或 Ctrl+V |

### 第 5 步：字出来了，但不对

| 现象 | 原因 | 处理 |
|---|---|---|
| 句子里偶尔丢一两个字 | 说太快、停顿被 VAD 判成句尾 | 停顿稍长一点；超过 30 秒的连续口述不做整段重解（会退回分段结果） |
| 某个专有名词总被听错 | 模型没见过 | 设置 → 文本 → 热词，只填这一个词（**别超过 3 个**），改完重载模型 |
| 单字错听（如"轮胎"听成"它"） | 1 字错 → 2 字对，文本替换会把所有同字改坏 | 这类救不了，只能靠多填热词或换更大的模型 |
| 标点太少 / 断句不对 | 断句阈值偏保守 | 用「书面化」档，它按语义补标点；「去口水词」只删字不改断句 |
| 输出繁体字 | 模型本身的倾向 | 设置 → 文本 → 打开"繁体转简体" |
| 整理后句子被改写过头 | 模型在发挥 | 降到「去口水词」；或换 MyVoiceTyping 模型（比通用 Qwen3 更克制） |
| 字是一句一句蹦出来的 | 正常 | 离线模型只能整段解码，停顿或说满一段才出一次 |

### 第 6 步：拼音打字相关（只影响拼音，不影响语音）

| 现象 | 原因 | 处理 |
|---|---|---|
| 语言栏里没有 "Verbalkey" | 引擎没装或没注册 | 托盘右键 → 「下载模型与组件…」→ 勾上拼音（打过勾的话会默认帮你勾好）→ 点一下按钮，它自己下、自己装、自己注册 |
| 点安装提示"词库不在程序目录里" | `assets/rime/ice/` 缺文件 | 同一个窗口点一次「重试」，会重新拉词库；纯语音用户可以无视这一整节 |
| 能选到输入法，但打不出字 | 后台服务是空壳（0 MB / 0 线程） | 退出并重开 Verbalkey；它启动时会按内存判断并重新拉起服务 |
| 任务栏「中/英」图标变回默认方块 | 拼音配置被别的工具重写 | 重新点一次「应用」；程序现在写配置是读改写合并，会保留图标项 |
| 候选窗样式不对 | 改完没重新编译 | 设置 → 拼音 → 「应用并重新编译」，约 10 秒 |
| 词库版本旧 | 需要手动更新 | 设置 → 拼音 → 词库更新（这是唯一会联网的按钮） |

### 第 7 步：性能与资源

| 现象 | 说明 |
|---|---|
| 内存 1 GB 以上 | 正常，识别模型常驻。开书面化再 +2.3 GB；可在设置里让整理层空闲退出 |
| 出字要等两三秒 | 默认行为：等整段重解 + 整理完才写。想早点看到字，改成"先写原文再确认替换" |
| 说很长一段更慢 | 重解耗时约每 1 秒音频 0.25 秒；超过 30 秒会放弃重解 |
| CPU 一直有占用 | 检查是不是整理层设成了常驻 |
| 日志里全是上屏文本 | 故意的，方便排查；已自动轮转封顶 16 MB |

## 常见问题

**能完全断网用吗？**
能。装完之后拔网线，识别、整理、拼音全都能用。联网只发生在两个手动动作：下模型、更新词库。

**会不会把我的话传上去？**
不会，代码里没有上传路径。你在 `logs/app.log` 和 `data/hotwords/corpus.jsonl` 里能看到它到底存了什么——都是明文，随时能删。

**为什么发 zip 而不是 setup.exe？**
发 zip 只是因为「装 Python」这一步已经不存在了——运行时已经打进 `_internal/`，
剩下只是复制文件。真正的 setup.exe 还要维护卸载、静默升级、权限和自动启动的边界情况，
收益不如先把这件事做对。要卸载就关掉自启、退出、删文件夹（拼音另到系统设置里卸）。

**发布包 72 MB 是不是少东西？**
不少。少的是模型（942 MB 起），它在首次启动时下载。这样改代码不用重新发 1 GB 的包，
模型换版本也不用重新发版。

**能商用吗？**
本项目代码 MIT。但随包/随下载的模型各有各的协议（Apache 2.0 / MIT / GPL-3.0），商用前自己核对上游原文，见[许可与来源](#许可与来源)。

**能换更大的模型吗？**
能。识别模型换 sherpa-onnx 的其它 ONNX 包，整理模型换任意 GGUF。但这台 CPU 上 4B 级别整理模型要 15 秒以上，不建议。

**会不会和微信输入法 / 搜狗冲突？**
不会。Verbalkey 是独立的托盘程序，通过模拟粘贴上屏，不注册为系统输入法。只有可选的拼音部分会注册成输入法。

## 模型

**用发布包的人不用看这一节**——首次启动的引导窗口会从这些地址自动下载。

仓库里不包含模型（合计 2–3 GB，且各有各的许可证），也不用网盘。所有文件指向上游官方源，一条命令自动下、自动校验、自动放对位置。

| 文件 | 大小 | 来源 |

| `models/polish/MyVoiceTyping-1.5B-Q4_K_M.gguf` | 940 MB | [ModelScope](https://modelscope.cn/models/botaruibo/MyVoiceTyping-1.5b-q4)，专为中文语音输入微调 |

整理模型**二选一**即可。推荐 MyVoiceTyping：小 280 MB，且是针对「语音转写文本 → 通顺书面语」训练过的；Qwen3-1.7B 是通用模型，也能用但没那么对口。

解压后的识别模型目录应该长这样：

```
models/sherpa-onnx-qwen3-asr-0.6B-int8-2026-03-25/
├── conv_frontend.onnx
├── encoder.int8.onnx
├── decoder.int8.onnx
└── tokenizer/{vocab.json, merges.txt}
models/silero_vad.onnx      ← 放 models/ 根目录，不是模型文件夹里面
```

设置 → 识别模型 → 下拉框选中它，点「重载识别模型」。窗口每次打开都会重扫目录，新拷进去的模型不用重启软件。

### 为什么不用网盘

网盘链接会失效、限速、没法校验完整性、也没有版本概念。而且这几个模型本来就有官方源，转存一遍只多了个会烂的中转站。

## 拼音输入（可选）

**只用语音的话，这一节可以跳过**——语音上屏不依赖拼音引擎。

Verbalkey 可以顺带托管一套拼音输入（小狼毫引擎 + 雾凇拼音词库），
这样语音和拼音共用一个「中/英」图标，候选窗样式也和语音浮窗统一。

**装法：在首次引导窗口里勾上「拼音输入法」，跟模型一起点一次按钮就行。**
之后想补装：托盘右键 → 「下载模型与组件…」，同一个窗口。

它会自己做四件事，全程几十秒到两分钟：

1. 缺组件就现下（引擎安装包 11.9 MB + 词库 16.9 MB，从 GitHub / 镜像拉，断点续传）
2. 静默安装引擎 —— **会弹一次系统授权框，点「是」**，这是唯一需要你动手的地方
3. 把词库铺到 `%APPDATA%\Rime`，改成 Verbalkey 的名字和图标
4. 重新编译（1–2 分钟，这期间语音功能照常可用）

装完窗口上会写「拼音输入法已就绪」，按 Win+空格 切过去就能打字。
如果授权框被关掉了，窗口会写「拼音输入法没装成」并给一个「再试一次」——
文件已经下好了，重试不会再下第二遍。

词库以后有新版本，在设置 → 拼音输入法里点「词库更新」即可。

### 为什么不把这些打进发布包

小狼毫和雾凇拼音都是 **GPL-3.0**。打进包等于替每个下载者承担 GPL 的源码提供义务，
而它们本来就有官方源。所以发布包里只带 librime 的官方部署器（BSD-3，4 MB，
没有它就没法自动重编译词库），其余运行时现下。

## 技术笔记

### 断句参数为什么不开放

参数不是我拍脑袋定的，是拿真实停顿量出来的：VAD 两端各补约 0.3 秒 padding，所以真实 1.5 秒的静音，VAD 只量到 0.92 秒。开放给用户改，改了必然对不上真实停顿，反而更容易出现"该断没断、不该断乱断"。

### 浮窗文字为什么要这么处理

**结论：用系统子像素渲染（ClearType），和微信输入法、Chromium、系统界面完全一致。**

这条路绕了很远，记录一下，省得以后再往反方向调：

1. **一开始嫌它有彩边，就关掉了。** 子像素渲染会在笔画两侧留极窄的橙蓝条纹，中文横竖笔画密，看着像毛刺。关掉它本身也不容易：Qt6 默认走 DirectWrite，不认 `NoSubpixelAntialias`，得先把字体引擎切回 GDI（`src/ui/__init__.py`）。
2. **关掉之后才发现踩了坑。** 灰度抗锯齿的物理上限就是「一个竖画只能落在整像素或半像素上」——跨两个像素就是 50%+50% 的灰。于是同一行里笔画深浅不一，整体发糊。后面做的 gamma 压深、笔画加粗（stem darkening），全都是在灰度这条路上往死里压，永远压不到子像素的锐度。
3. **决定性证据**：随手量了屏幕上任意一个 Chromium 界面文字，墨迹像素 1085 个，其中 1073 个带彩边（98.9%）。桌面端看着清晰的文字，全都在用子像素。彩边只占边缘不到一个像素的宽度，正常观看距离下人眼会把它融合成更高的亮度对比——所以你看不见。
4. **所以正确的做法是加回来**：窗口不透明 + `QFont.PreferAntialias` + 直接画到窗口（不能走离屏位图，位图拿不到子像素）。

代价：整个进程被钉在 GDI 渲染引擎上，设置页也跟着走 GDI。GDI 只有 400 / 700 两档字重，所以设置页标题不用 `font-weight:600`（会被压成更黑的 700），改成靠字号分层。

灰度模式还留着：环境变量 `VERBALKEY_INK_GRAY=1` 切回灰度（无彩边，但边缘发灰）。那一档才有 gamma / 加粗参数可调：`VERBALKEY_INK_GAMMA`（默认 0.48）、`VERBALKEY_INK_STEM`（默认 0，建议 0～0.3）。

### 本机实测（Ryzen 5 4600H / 6 核 / 15 GB）

| 环节 | 实测 |
|---|---|
| ASR 模型冷启动 | 4.4–5.5 秒（只在启动时一次） |
| 单句识别（2 秒音频） | 1.1 秒 |
| 单句识别（4 秒音频） | 2.1 秒 |
| 整段重解 | 约每 1 秒音频 0.25 秒 |
| 去口水词（规则） | 1 毫秒以内 |
| 整理层冷启动 | 2.0–2.5 秒（按热键时就开始点火） |

## 从源码打包成 exe

先激活虚拟环境（`.venv\Scripts\activate`），然后：

```
python -m PyInstaller --noconfirm --clean verbalkey.spec
```

**别直接敲上面这条**——PyInstaller 的 COLLECT 会把整个 `dist/Verbalkey` 删掉重建，里面的 `config.json`、`data/`、`logs/` 会一起没。用仓库里的脚本：

```
python tools/build.py
```

它会先备份 `config.json` / `data/` / `logs/app.log`，打完再还原，并把 `models`、`bin` 重建为目录联接。

产物在 `dist/Verbalkey/`，但**只有代码**。把这三样拷进去才能独立运行：

```
dist/Verbalkey/
├── Verbalkey.exe
├── models/      ← 从项目根复制
├── bin/         ← 从项目根复制
├── config.json  ← 从项目根复制
└── _internal/   ← PyInstaller 运行时，别动
```

用目录模式而不是单文件：单文件每次启动要把 175 MB 解到临时目录，托盘常驻程序开机就等好几秒，不值得。

程序目录可以整个搬到别的电脑（Win10 以上、已装 VC++ 运行库）。首次运行会在程序目录建 `logs/`，崩溃会写 `logs/crash.log`。

配置里的模型路径优先用存在的绝对路径，找不到就按 `bin/` / `models/` 重新拼到程序目录下——所以整包搬迁后整理功能不会失效。

### 打发布包

```
python tools/release.py --build     # 先打包再压 zip
python tools/release.py             # 用现有 dist 直接压
```

产物：`release/Verbalkey-<版本>-win64.zip`，约 72 MB。脚本会自动剔除
`models/`、`bin/`、`data/`、`logs/`、`config.json` 和拼音的原始组件
（安装包 + 词库），并复查一遍确认运行时齐全、隐私文件没混进去。
把 zip 挂到 GitHub Release 即可。

版本号在 `src/config.py` 的 `APP_VERSION`，改一处就行。
