# Verbalkey（Windows 本地语音输入）

按住热键说话，浮窗实时出字，松开即上屏。全程离线，录音不离开本机。

- 识别：Qwen3-ASR-0.6B int8（sherpa-onnx，纯 CPU）
- 分句：Silero VAD + 短段合并 + 强制切分兜底（参数已固化，界面不暴露）
- 上屏：剪贴板 + 模拟粘贴
- 整理：llama.cpp 本地 Qwen3-1.7B Q4_K_M

## 两种按键模式（设置 → 热键）

| 模式 | 怎么用 | 适合 |
|---|---|---|
| **按住说话**（默认） | 按住不放录音，松开就识别上屏 | 说完即走的短句 |
| **按一下切换** | 短按一下开始，再按一下结束 | 长段口述，手不用一直按着 |

按键本身也能换：右 Alt（默认）/ 右 Ctrl / 右 Shift / CapsLock / F5 / F8 / 反引号。改完立即生效。

## 本机实测（Ryzen 5 4600H / 6 核 / 15 GB）

| 环节 | 实测 |
|---|---|
| ASR 模型冷启动 | 4.4–5.5 秒（只在软件启动时发生一次） |
| 单句识别（2 秒音频） | 1.1 秒 |
| 单句识别（4 秒音频） | 2.1 秒 |
| 去口水词（规则） | 1 毫秒以内，说完就生效 |
| 整理层冷启动 | 2.0–2.5 秒（按下热键时就开始点火，听不见） |
| 整理层热运行 | 0.4 秒（20 字）/ 1.2 秒（46 字）/ 2.4 秒（88 字） |
| 常驻内存 | ASR 约 1.1 GB；整理层用得到才起，空闲 5 分钟退出（可设常驻） |

也就是说：**停一下顿，1–2 秒后上一句就出现在浮窗里**。说的时候浮窗只显示，
松开才写进输入框——可以随时反悔。

如果一口气不停顿，也会按「最长等字间隔」（默认 6 秒）先出一次字。
强制出一次字，不会让你干等着看不到东西。

## 安装

需要 Windows 10/11 + Python 3.10 以上（安装时勾选加入 PATH）。

1. 把仓库克隆/解压到一个目录（建议纯英文路径，个别库对中文路径处理不一致）
2. 双击 `install.bat`：建 `.venv`、装依赖、下载 VAD 模型
3. 按下一节把识别模型放进 `models/`，再按「口述整理怎么配」放整理模型
4. 双击 `start.vbs` 静默启动，或 `run.bat` 带控制台启动（调试用）

托盘里出现粉色图标即表示运行。`install.bat` 只需要跑一次。

## 模型

仓库里**不包含模型**（3.1 GB，且各有各的许可证）。需要自己下载，放对位置即可。

### 识别模型（必需，约 950 MB）

```bash
curl -L -O https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/sherpa-onnx-qwen3-asr-0.6B-int8-2026-03-25.tar.bz2
tar xjf sherpa-onnx-qwen3-asr-0.6B-int8-2026-03-25.tar.bz2
mv sherpa-onnx-qwen3-asr-0.6B-int8-2026-03-25 models/
curl -L -o models/silero_vad.onnx https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/silero_vad.onnx
```

解压后目录里应该有：

```
conv_frontend.onnx
encoder.int8.onnx
decoder.int8.onnx
tokenizer/{vocab.json, merges.txt}
silero_vad.onnx      ← 放 models/ 根目录，不是模型文件夹里面
```

设置 → 识别模型 → 下拉框选中它，点「重载识别模型」。窗口每次打开都会重扫目录，
新拷进去的模型不用重启软件。

**下载慢的坑**：GitHub release 走代理只有约 70 KB/s，838 MB 要 3 小时。
用迅雷 / IDM 拉会快很多；国内源（ModelScope）只有 transformers 原始格式，
不是 sherpa-onnx 要的 ONNX 包，别下错。

### 整理模型（可选，只有「书面化」档才用）

- `Qwen3-1.7B-Q4_K_M.gguf`（约 1.2 GB）：从 Qwen 官方 GGUF 仓库下载 Q4_K_M 量化版，
  放 `models/polish/`
- `llama-server.exe` 和同目录的 dll：从 llama.cpp 的 Windows 发布包取（实测 build 11934），
  放 `bin/llama/`

不装也能用：设置 → 口述整理 → 强度选「关闭」或「去口水词」，这两档不跑大模型。

## 使用

| 操作 | 说明 |
|---|---|
| 按住 右 Alt | 开始录音，浮窗实时显示已识别的文字 |
| 松开 | 立即上屏原文，随后后台整理 |
| 按 右 Ctrl | 用整理版替换刚上屏的原文（45 秒内有效） |
| 点浮窗「用整理版」 | 同上，懒得按键时用鼠标 |
| 点浮窗右上角 × | 收起浮窗，整理结果直接丢掉 |
| 单击托盘图标 | 打开设置 |
| 右键托盘 | 设置 / 重载模型 / 退出 |

确认键默认右 Ctrl，和录音键（右 Alt）分开，不会打架。在设置 → 热键里可以换成
右 Alt / 右 Shift / F5 / F8 / Enter / 反引号；如果和录音键选成同一个，界面会提示。

## 设置项说明

**通用** — 开机自启、浮窗位置、浮窗字号（小 16 / 标准 18 / 大 20）、
上屏方式（自动 / 仅 Ctrl+V / 仅发消息）。字号改完立即生效。

**热键** — 触发方式（按住说话 / 按一下切换）+ 录音键，可选右 Alt（默认）、右 Ctrl、
右 Shift、CapsLock、F5、F8、反引号；下面单独一行选整理结果的确认键（默认右 Ctrl）。
已知限制：全屏程序和以管理员身份运行的窗口会拦掉全局热键。

**语音与识别** — 麦克风设备、推理线程。断句参数不对外开放，原因见下一节。

**文本** — 繁体转简体（Qwen3-ASR 常输出繁体，建议开）、替换词表（`原文=替换后`，一行一条）、
热词（逗号分隔，走模型偏置通道，改完需重载模型）。

**口述整理** — 三档强度：关闭 / 去口水词 / 书面化。去口水词走本地规则，瞬时；
书面化跑本地模型，一句话约一秒。
下面一行决定整理结果怎么给你：默认「先上屏原文，整理完按确认键替换」；
打开「直接输入整理版」就变成等整理完一次性写进光标，慢两三秒但不用再按确认键。
设置 llama-server.exe 路径和 GGUF 模型路径后生效；没配也能用，会自动降级成规则整理。

**识别模型** — 切换已安装的模型，或打开模型目录自己放新的进去。

## 口述整理怎么配

已经配好了：`bin/llama/llama-server.exe` + `models/polish/Qwen3-1.7B-Q4_K_M.gguf`。
整理层默认不常驻：用到才起，空闲 5 分钟自动退出（设置里可以改成常驻）。

三档强度：

- **关闭**：一个字节都不改。会议记录、病历这类要逐字忠实的场合用它。
- **去口水词（L1）**：删掉「嗯、啊、那个、就是说」和结巴重复，不动措辞。
  **走本地正则，毫秒级完成，不启模型、不占内存**，所以这一档是真正的「说完就干净」。
  为什么不用模型：1.7B 在这一档上摇摆得厉害，同一句话有时一个字不改，
  有时把「考虑考虑」改成「考虑」（把正常叠词压成了病句）。确定性的活儿交给规则。
- **书面化（L2）**：补标点、理顺断句。跑本地模型，**带 4 组对话示例**（few-shot）。
  实测把「嗯那个我想问一下咱们这个陪护服务一天是管多少钱然后是不是可以按小时算」
  整理成「我们这个陪护服务一天是管多少钱，能不能按小时算？」。
  加示例的原因：零样本时 1.7B 会「看心情」，同一段话有时改得很好、有时一个字不动
  原样复述。给了示例之后模仿倾向强很多，碎句也少了。
  万一还是原样复述，会自动换更高的温度重试一次。

### 速度是怎么压下来的

1. **按下热键就开始点火**：llama-server 冷启动 2 秒多，等松键才起就要干等；
   现在你还在说的时候它已经在加载，进程优先级调成「低于正常」，不跟语音识别抢 CPU。
2. **system 指令 + user 原文分开**：指令固定不变，llama-server 的前缀 KV 缓存能命中，
   同一句话第二次起快一倍多（2.9 秒 → 1.2 秒）。顺便也修了「模型把指令当上文、
   原样复述原文」的毛病。
3. **关掉 Qwen3 的思考模式**（`enable_thinking: false`）：不关会多烧 160 token、多花 8 秒。
4. **常驻内存开关**：设置 → 口述整理 → 本地模型。开了省掉每次 2 秒冷启动，
   代价是常驻约 2.3 GB。

整理不阻塞上屏：原文先写进输入框，整理在后台跑，跑完浮窗提示按确认键替换。
要是嫌多按一下麻烦，去设置 → 口述整理打开「直接输入整理版」，
就变成整理完直接写进去（代价是等整理完才开始出字）。

要换模型就下别的 GGUF（4B 在这块 CPU 上要 15 秒以上，不建议），
在设置 → 口述整理里改路径。

## 排错

| 现象 | 原因 / 处理 |
|---|---|
| 托盘提示「未找到识别模型」 | 模型没放对位置，见「识别模型」一节 |
| 按住热键没反应 | 当前窗口是全屏或管理员权限；先用普通窗口点一下 |
| 说完了没出字 | 多半是麦克风选错，去「语音与识别」换设备 |
| 说话时一直不出字 | 正常。一句话没停顿也要 6 秒才先出一次字（为了准确率的取舍） |
| 某个词总是听错 | 设置 → 文本 → 热词，填那一个词（**不超过 3 个**，填多了模型会把词表当正文念出来） |
| 字是一句一句蹦出来的，不是逐字跟 | 正常。离线模型只能整段解码，停顿 0.5 秒或连续说满 6 秒才出一次 |
| 浮窗的字看着不清晰 | 见下方「浮窗文字为什么要这么处理」。嫌小就调 设置 → 通用 → 浮窗字号 |
| 整理断句不对 | 用「书面化」档（走模型 + 示例）；「去口水词」只按规则删字，不改断句 |
| 浮窗显示结果但没进输入框 | 光标不在输入框里；文本已留在剪贴板，自己按 Ctrl+V |
| 剪贴板里是旧内容 | 上屏成功后会主动还原你原来的剪贴板，这是故意的 |
| 整理一直提示失败 | 检查 llama-server 和 GGUF 路径；没配会用规则整理兜底 |

日志在 `logs/app.log`。

## 浮窗文字为什么要这么处理

**结论：用系统子像素渲染（ClearType），和微信输入法、Chromium、系统界面完全一致。**

这条路绕了很远，记录一下，省得以后再往反方向调：

1. **一开始嫌它有彩边，就关掉了。** 子像素渲染会在笔画两侧留极窄的橙蓝条纹，
   中文横竖笔画密，看着像毛刺。关掉它本身也不容易：Qt6 默认走 DirectWrite，
   不认 `NoSubpixelAntialias`，得先把字体引擎切回 GDI（`src/ui/__init__.py`）。
2. **关掉之后才发现踩了坑。** 灰度抗锯齿的物理上限就是「一个竖画只能落在整像素
   或半像素上」——跨两个像素就是 50%+50% 的灰。于是同一行里笔画深浅不一，
   整体发糊。后面做的 gamma 压深、笔画加粗（stem darkening），全都是在灰度
   这条路上往死里压，永远压不到子像素的锐度。
3. **决定性证据**：随手量了屏幕上任意一个 Chromium 界面文字（WorkBuddy 面板里的
   「新建任务」），墨迹像素 1085 个，其中 **1073 个带彩边（98.9%）**。
   桌面端看着清晰的文字，全都在用子像素。彩边只占边缘不到一个像素的宽度，
   正常观看距离下人眼会把它融合成更高的亮度对比 —— 所以你看不见。
4. **所以正确的做法是加回来**：窗口不透明 + `QFont.PreferAntialias` +
   直接画到窗口（不能走离屏位图，位图拿不到子像素）。

微信输入法的实际实现也印证了这一点：`wetype_tip_core.dll` 里能搜到
`D2D1CreateFactory`、`DWriteCreateFactory`、`d2d1.dll` —— 候选词是
Direct2D + DirectWrite 画的，而且它目录里**没有任何自带字体**，用的就是系统雅黑。
清晰度来自渲染方式，不是字体。

### 灰度模式还留着
环境变量 `VERBALKEY_INK_GRAY=1` 切回灰度（无彩边，但要接受边缘发灰）。
那一档才有 gamma / 加粗参数可调：`VERBALKEY_INK_GAMMA`（默认 0.48）、
`VERBALKEY_INK_STEM`（默认 0，建议 0～0.3，0.8 会粘连）。

## 打包成 exe

先激活虚拟环境（`.venv\Scripts\activate`），然后：

```
python -m PyInstaller --noconfirm --clean verbalkey.spec
```

打包会删掉整个 `dist/Verbalkey`。**别直接敲上面这条**——仓库里的 `tools/build.py`
会先备份 `config.json` / `data/` / `logs/app.log`，打完再还原，并把 `models`、`bin`
重建为目录联接：

```
python tools/build.py
```

产物在 `dist/Verbalkey/`，但**只有代码**。把这三样拷进去才能独立运行：

```
dist/Verbalkey/
├── Verbalkey.exe
├── models/      ← 从项目根复制（2.2 GB）
├── bin/         ← 从项目根复制
├── config.json  ← 从项目根复制
└── _internal/   ← PyInstaller 运行时，别动
```

用目录模式而不是单文件：单文件每次启动要把 175 MB 解到临时目录，
托盘常驻程序开机就等好几秒，不值得。

程序目录可以整个搬到别的电脑（Win10 以上、已装 VC++ 运行库）。
首次运行会在程序目录建 `logs/`，崩溃会写 `logs/crash.log`。

**配置里的模型路径**优先用存在的绝对路径，找不到就按 `bin/` / `models/`
重新拼到程序目录下 —— 所以整包搬迁后整理功能不会失效。
